# Deleted-install operator recovery

This private Windows x64 helper responds to an operator deleting all of `Program Files/USB Link`. From 0.10.4 the normal installer performs the same narrowly verified cleanup after selected components are ready. The private kit delegates inspection/removal to that production verifier and uses a Go overlay only for its separate reinstall observation. Neither route restores a missing binding by adopting an existing service. The ordinary installer does not include this kit's pinned external-launch or observation entry points.

The reviewed state is a missing program root, a stopped/PID-zero `USBLinkCore` pointing to `0.9.3/USB-Link.exe --core-service`, and the product's exact 0.8.139 uninstall registration. Either old object may be absent after an interrupted repair. Other paths, versions, commands, ownership, service policies or running USB Link processes stop the tool. It does not stop services, change their configuration, or modify accounts, shares, drivers, firewall/network settings or protected recovery journals.

Before removal, it saves and flushes a protected native configuration/security backup in `ProgramData/USB Link/DeletedInstallRecovery/<time>/before.json`, checks the backup, and rechecks both residuals. It holds the normal core lifecycle mutex. Partial failures retain the backup and can be retried only if remaining objects still match. A deleted service must actually disappear before installation starts.

Version 0.10.8 permits discarding the exact legacy leaf when its ACL contains the reported inherited Terminal Server Users ACE (`S-1-5-13`, mask `0x0003001f`, flags `0x10`). This is not a trusted-writer exception: registry values never authorize service adoption or command execution. The fixed nine-value/no-child profile, privileged owner, missing-root checks, service security and backup/recheck sequence still apply. Explicit grants, different principals and additional rights remain rejected. Windows execution of this recovery path remains to be verified on the affected machine.

The returned 0.10.8 service report identified a second mismatch: its display name is `USBLinkCore`, while the verifier required `USB Link`. Version 0.10.9 accepts either exact display name only in legacy residual deletion, and reports the specific mismatched configuration fields on rejection. The returned command, account, start type, description and recovery policy match the existing checks; none of those checks is relaxed. Windows installation with 0.10.9 remains unverified.

The new installer is build-pinned by SHA-256 and held open denying write/delete throughout launch. Local .NET and Wintun must pass the existing pinned dependency checks before residual removal. The default small online kit runs `--prepare-components` after the residual preflight: it reuses verified components, downloads only missing .NET/Wintun from the production pinned catalog, and retains both residual objects on cancellation or preparation failure. Apple components are handled by the normal application's device-specific prompts. The optional offline kit supplies pinned third-party packages and prepares them without network access. UAC must run in an interactive administrator session.

The tool waits for fixed-layout 0.10.0 registration, verified source/binding, the completed installation transaction and authenticated initialization over five consecutive observations. This proves installation and core initialization only. It does not claim USB connectivity, SMB access or browser throughput acceptance. Reports contain only installation state and bounded startup stage/error fields; full diagnostics and original recovery journals stay on Windows.

Build with `python3 scripts/windows-deleted-install-repair/build.py --installer-sha <reviewed SHA256>` for the small `-online` kit. Add `--offline-components` only when the affected Windows machine needs offline preparation. The builder refuses to mix files into an existing nonempty kit. Windows native vet/cross-build can run on macOS; execution and device acceptance require the affected Windows machine. Do not distribute this operator recovery kit as a public USB Link release.

The 0.9.5 kit is paused. The private builder now targets fixed-layout 0.10.0 and requires an explicit reviewed installer SHA256. It verifies the completed installation transaction and authenticated initialization, not only SCM Running. Windows execution remains pending.
