# Private offline component bundle

The user-facing folder contains one short `install_all.bat` and five original official component downloads. There is no embedded native helper, encoded executable, PowerShell payload or extra user-facing script. The BAT elevates normally, skips a present .NET 10.0 runtime and Apple Mobile Device Service, and runs only the two actual installers in order. .NET uses its official `/install /passive /norestart` options; Apple retains its original installation/license UI.

Wintun is a DLL ZIP, Zadig is a portable device driver tool, and the Apple CAB is a driver package. They are not runtime installers to blindly execute. The BAT copies these three original packages, without replacing existing files, to `%ProgramData%/USB-Link Components`. USB Link accepts that shared cache regardless of its creator, checks the compiled catalog hashes/signatures, and reuses already functional device drivers. It does not require a product installer receipt for existing system .NET, Apple service or a compatible Wintun DLL. Downloads happen only when required compatible files are unavailable.

Build with `python3 scripts/windows-offline-components/build.py` after supplying the original packages described in `packages.json`. The builder validates official hashes and the six-file ZIP, then replaces the old generated folder/archive. Build records stay outside the visible folder. Windows native installation and hardware acceptance remain pending.

References: [Microsoft .NET installer options](https://learn.microsoft.com/en-us/dotnet/core/install/windows), [Wintun's ZIP/DLL distribution](https://www.wintun.net/), [Zadig's device driver role](https://zadig.akeo.ie/), and [TechPowerUp's single-BAT runtime bundle](https://www.techpowerup.com/download/visual-c-redistributable-runtime-package-all-in-one/).
