# Private offline component bundle

Build with `python3 scripts/windows-offline-components/build.py` after supplying the five catalog-pinned original downloads under `offline-components/` (or the legacy `packages/` subdirectory). The native helper is tagged `usblink_offline_components`; it is not part of the public USB Link executable. Original third-party packages remain local-only.

The generated user-facing directory has exactly six files: `install_all.bat` and the five unmodified original packages. The BAT carries its compressed native helper, extracts it to a unique Windows temporary directory, verifies its compiled SHA256 and retains a read handle denying write/delete during execution. It requests elevation once, waits for each step, then deletes the temporary helper. It keeps transcripts and structured results under `%TEMP%/USB-Link-ComponentLogs/`, outside the bundle. Its optional `--no-pause` argument is for the private deleted-install coordinator.

The helper verifies every selected package and official EXE signature before creating the protected ProgramData component directory. It reuses the production directory protection, runtime detection, asset mutexes, signature/hash checks and extraction logic. The HTTP transport rejects downloads. Existing verified components are reused. Wintun and the Apple driver package are prepared for the main application's device-specific use; Zadig is cached, without launching device replacement. Missing Apple communication support opens the original official installation/license UI. The batch does not silently accept Apple terms or force reboot. A reboot-required result exits 3010 and preserves the completed steps for a rerun.

The builder preserves editable legacy support files and all checksum/build evidence outside the visible directory. It verifies the staged BAT's embedded-helper round trip and the six-file ZIP, then publishes the new flat directory and replaces the prior generated archive. Pipeline tests cover corrupt-package preflight, reuse, failure/cancellation and restart results. Native Windows installation and new-system hardware acceptance remain pending.

This uses the single-BAT entry pattern described by [TechPowerUp's runtime bundle](https://www.techpowerup.com/download/visual-c-redistributable-runtime-package-all-in-one/). Windows Installer [success and restart codes](https://learn.microsoft.com/en-us/windows/win32/msi/error-codes) are handled separately from failures.
