# 安装、更新与卸载规范

从 0.10.0 起，Windows 只有一个正式程序目录。安装 EXE 从下载目录或 U 盘运行，完成后退出，不复制到 Program Files 中长期存放。

| 目录 | 用途 | 成功更新后 |
| --- | --- | --- |
| `Program Files/USB Link/App/` | 当前核心、程序凭据 | 保留当前一份 |
| `Program Files/USB Link/App/Desktop/` | 当前界面与界面所需 DLL | 随当前程序整体核验 |
| `ProgramData/USB Link/State/` | 核心登记、更新事务、连接设置 | 保留配置与完成记录 |
| `ProgramData/USB Link/State/security/` | SMB 账户、权限、安全策略 | 仅管理员与 SYSTEM 可访问 |
| `ProgramData/USB Link/Dependencies/` | 已核验私有运行时、组件和下载缓存 | 复用合格组件 |
| `ProgramData/USB Link/Updates/Candidate/` | 本次待安装的完整程序 | 删除 |
| `ProgramData/USB Link/Updates/Previous/` | 本次更新恢复用完整副本 | 新核心初始化被核验后删除 |
| `ProgramData/USB Link/Shared Files/` | 新安装默认共享资料 | 更新、卸载均保留资料 |

已有共享资料、仍承担硬件恢复的 Windows Temp 原值记录及旧维护事务保持原路径。其路径不直接决定文件是否可删除。旧版程序和桌面运行时会在启动任务移到新目录、依赖及文件内容核验通过后清理；没有永久“上一版本程序目录”。无法核验、仍被引用或被占用的文件会保留并报告待处理。

构建输出中的安装包另行执行“当前候选 + 一个用户选定的可回退安装包”保留规则。当前回退安装包仍是已在设备上验收过的 0.8.139，构建成功的候选不会自动取代它。

## 安装向导与残留检查

0.10.5 的安装向导使用 Windows 标准标题栏、系统对话框字体、按钮、勾选框、分组框、文本框及进度条。系统负责绘制背景、控件和分隔线，已移除自绘侧栏、卡片、色块和配色覆盖。EXE 保留 Common Controls v6 清单，字体通过系统对话框指标按 DPI 读取，不增加界面组件安装。

0.10.4 欢迎页只显示简短的安装说明。点击「安装诊断」才会只读检查本机的 USB Link 卸载登记、核心服务命令及状态、所指程序文件是否存在，以及当前／旧版安装凭据是否存在。检查不创建产品目录、不读取账户密码，也不调用安装、迁移或修复流程。服务管理器和登记仅以查询权限打开；读取失败显示“无法确认”，不会认定为不存在。可重新检查，或通过 Windows 保存对话框把 JSON 报告保存到自选位置。

发现已删除程序对应的残留登记时显示原因。诊断页可以返回原页面；安装失败后保存的报告也包含本次失败原因。检查报告本身不证明产品所有权，不能单独授权删除服务或登记。

## 更新事务

从 0.10.2 起，运行安装 EXE 会先显示原生向导：欢迎 → 许可条款 → 组件勾选 → 安装摘要。未同意条款或在这些页面取消，不准备组件；点击“安装”后才开始检查、准备已选组件并进入下述事务。安装中取消会等候安全恢复，完成页可选择启动程序。向导无需桌面运行库。

1. 本地管理员、产品、账户身份、服务、现有安装登记及重启待删除项检查通过后，记录候选文件清单。
2. 从 EXE 内置发布内容准备完整候选；按字节摘要独立读取核验。中断后的临时文件须与同一发布内容逐字节验证为前缀，才能继续准备；外来内容保留。
3. 请求经过来源、账户及窗口核验的旧登录界面执行自己的“结束”动作。后台核心执行正常停止及原值恢复；不通过终止核心绕过恢复。
4. 核验临时恢复副本，把已停止的服务暂时登记到该副本，使用手动启动策略。原程序文件只按已登记清单删除。
5. 发布到固定 `App`，更新服务、开始菜单及原有开机启动任务。新核心完成连接设置初始化、历史 USB／网络恢复后，由经过服务 PID、创建时间、来源和 SYSTEM 身份核验的核心写入验收记录。
6. 完成记录之后清理候选及临时恢复副本。清理中断只续接清理，不把已成功启动的版本退回旧版。失败或取消时保留恢复意图，恢复原有文件、服务来源、启动策略和登记。

同一版本、不同 EXE 内容不能覆盖已有安装；降级要求先卸载。未完成事务须由原安装包续接，不能用另一个包猜测接管。更新窗口可显示准备、正常关闭、替换、核验、清理或恢复状态。

## 卸载与重装

卸载仍从本机安装来源发起并确认。先正常关闭已核验的登录界面，恢复本程序拥有的 USB、网络和 Guest 设置，关闭自建共享、移除专用账户和服务；恢复未确认则保留程序和原值记录。只删除已经核验的程序与私有组件，保留用户资料、官方 Apple 软件、共用驱动及诊断依据。

自身运行中的 EXE 可以安排在重启后删除。安装器会读取 Windows 待删除任务：上次卸载尚需重启时阻止重装，避免旧待删除路径删掉新 `App`。

固定布局的正式完成记录与绑定保留在 ProgramData。手动删除程序文件后，同一个原始安装包可恢复其完全一致、曾验收的发布内容；要求原绑定及安装登记吻合、服务停止且无外来配置，不更改服务命令。缺失原凭据的旧版安装不被自动接管。0.10.4 将已确认的旧版残留处理接入正常安装流程：只允许完全缺失的程序根目录、无新布局凭据或事务、精确的 0.8.139 产品卸载登记、停止且 PID 为零的 0.9.3 核心服务。原生检查还核验登记值类型与数量、命令、所有者、ACL 和服务执行策略；改变过的状态或其他运行中进程阻止处理。0.10.6 修正了把通用读取／执行误判为写入的掩码，补充检测创建注册表链接的权限。可写主体仅允许 SYSTEM、Administrators 或本次交互式提升后的管理员账户的精确 SID；其他账户或仅匹配 SID 前缀都不能通过。原有所有者检查继续生效。核心服务也修正了通用读取误判，通用执行仍按服务启动／停止权限处理，不与注册表的只读执行含义混用。

返回的 0.10.5 报告表明失败发生于登记的 ACL 检查，尚未清理残留。该报告没有原始 ACL，不能据此确定触发的是哪一项。新版只读报告增加该产品登记和核心服务的所有者／DACL 描述，拒绝未知写入时同时报告具体 SID、权限掩码和标志，避免仅凭错误名推断本机配置。

先准备所有选中的组件。准备失败或取消不清理残留。然后持有核心生命周期锁，写入并刷新 `ProgramData/USB Link/DeletedInstallRecovery/<time>/before.json`，按受保护句柄独立读取核验，再重复检查残留。只删除已核验的停止服务及旧卸载登记；服务实际消失后才开始新安装。中途失败保留备份，只允许仍符合原条件的对象继续处理。没有新布局凭据就不接管服务，不修改旧服务命令。

清理保留账户、共享资料、Windows Temp 中的硬件恢复记录及网络／驱动设置；它不是卸载恢复的替代流程。新核心仍须通过原来的初始化、恢复和安装验收步骤。上述确认来自返回的安装状态报告，实际清理与重新安装还需在受影响 Windows 上验收。

## 参考与实现选择

权限判断按微软的[注册表通用权限映射](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/opening-a-handle-to-a-registry-key-object)与[服务权限定义](https://learn.microsoft.com/en-us/windows/win32/services/service-security-and-access-rights)区分对象类型，不把所有通用权限都归为写入。


- [Windows Installer 重大升级](https://learn.microsoft.com/en-us/windows/win32/msi/major-upgrades)：维持产品升级身份，核对已有安装，区分升级与真正卸载。
- [Windows Installer 安装回退](https://learn.microsoft.com/en-us/windows/win32/msi/rollback-installation)：安装失败恢复，成功后清理事务备份。
- [Inno Setup 默认安装目录](https://jrsoftware.org/ishelp/topic_setup_defaultdirname.htm)和[卸载清理](https://jrsoftware.org/ishelp/topic_uninstalldeletesection.htm)：复用固定程序目录，只清理已知程序文件，保留用户和未知资料。
- [Velopack 集成说明](https://docs.velopack.io/integrating/overview)：单一 `current` 活动目录，设置及日志位于活动内容之外。
- [Squirrel 更新流程](https://github.com/Squirrel/Squirrel.Windows/blob/develop/docs/using/update-process.md)：常驻版本目录不符合本项目这次要求，因此不采用它的目录保留方案。

采用上述目录与事务原则，继续使用已有的原生 Windows 身份核验、受保护记录及硬件恢复协调。未仅仅套一层第三方安装向导去绕过 USB 原值恢复。

## 验证边界

已加入真实临时文件系统和事务故障测试：成功只留下当前程序；文件占用保留候选；中断复制／清理可续接；禁止覆盖竞争目标；拒绝外来文件、目录、链接和变更过的临时内容；失败恢复；验收后清理失败不回退；取消及身份变化。

这些测试和 Windows 交叉编译／静态检查不能替代 Windows 上的 SCM、界面关闭、安装中断、卸载重启以及真实 Mac／iPad 连接验收。旧修复入口保持暂停，本轮不在用户 Windows 上安装。
