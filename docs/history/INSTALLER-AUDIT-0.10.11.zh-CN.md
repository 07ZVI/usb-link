# 0.10.11：启动入口与中断事务恢复

## 本次 Windows 报告确认了什么

返回的 0.10.10 报告显示：包预检、Wintun、.NET 准备均通过；安装失败于 `STARTUP_TASK_RECEIPT_CHANGED`，随后的回滚失败于 `shortcut update failed or ownership changed`。最终事务为 `restoring`，34 个新文件、0 个旧文件；服务、绑定、卸载登记均已不存在。

0.10.10 的报告没有记录任务或快捷方式目标，因此不能仅凭错误声称某个具体版本的入口已经损坏或缺失。之前审查遗漏了首次安装的已有启动入口检查，且没有覆盖这种回滚阻塞；0.10.10 的自动测试通过不足以证明完整 Windows 安装通过。

## 修复范围

- 安装前同时查询当前用户的两种产品任务名及两个开始菜单入口。任务与快捷方式独立检查；报告保留目标路径、状态和具体校验错误。没有因为服务或卸载登记不存在而忽略它们。
- 独立处理“旧版本目录整个消失”的启动入口。路径必须严格位于系统 Program Files 下本程序的数字版本目录；任务还必须匹配产品描述、用户 SID、交互登录、最高权限、单一 `--resident` 动作和既有登录触发器。运行中或排队中的旧任务不会自动删除。
- 清理前将原始 XML / 快捷方式字节持久备份到 `%ProgramData%\USB Link\State\IntegrationRecovery`；全部检查和备份通过后才开始删除，每次删除前重新查询，删除后再读回。备份仅用于保留现场，不会自动执行或导入。
- 不把存在但无法验证的版本目录判为孤立入口；不接管外部路径、改过的动作、另一个用户的任务或重定向路径。普通开机任务的来源验证保持严格。
- 首次安装回滚只删除指向这次失败的 `App` 的产品入口；历史目标不会因回滚而被当作本次新增内容删除。
- 新版可以完成同一用户、受保护日志、无旧版本的 `restoring` 回滚。旧日志与文件哈希保持原样，由原事务验证服务和文件，回滚完成并写入 `rolled-back` 后才创建新版事务。其它仍在安装中的事务依然需要原包，不允许用新版内容冒充旧版继续发布。
- 已有受保护事务暂时缺少 App 时，预检仅将它交回原事务恢复；该状态不提供入口删除或程序执行权限。
- 提交前复审修正了报告错误归属：一个任务校验失败不再给其它正常任务附上同一错误；孤立任务的运行状态检查仍逐项执行，任一失败继续阻止清理。增加混合正常/失败任务与运行中/排队任务回归测试。

## 验证与边界

本轮增加路径越界、当前目录误判、不同用户/阶段/版本/清单接管、备份失败、入口变化、部分清理重试、回滚不执行候选版本测试；增加真实 Windows 临时快捷方式的只读 COM 测试，不修改系统开机任务。

完整 Go 竞态测试、Windows 交叉编译与静态检查、实际归档/最终 EXE 的安装文件契约测试、发布脚本测试和包审计的结果随交付记录保存。Windows 原生测试在本机只能编译，未执行；目标 Windows 的完整安装与设备连接仍须以现场结果为准。

接口依据：[Microsoft Task Scheduler ITaskFolder](https://learn.microsoft.com/en-us/windows/win32/api/taskschd/nn-taskschd-itaskfolder)、[Microsoft WSH 快捷方式](https://learn.microsoft.com/en-us/troubleshoot/windows-client/admin-development/create-desktop-shortcut-with-wsh)。
