# 0.9.5 启动与重装审查

本轮对照源码、提交历史及同项目对话。0.9.5 是修复候选，软件检查通过不等于 Windows 实机启动、USB 或 SMB 已验收。当前没有继续远程安装。

## 已合入的改动

| 对照记录 | 当前源码中的结果 |
| --- | --- |
| 整理项目架构并分离第三方组件 | 模块化源码；Apple、Wintun、Zadig、.NET 从固定官方来源获取，优先复用有效组件；默认关闭的 Windows → Mac 互联网共享。 |
| 评估项目开源准备度 | 中英文文档、发布审查；临时文件传输、WebDAV 和开发者远程升级入口从公开程序移除。自用离线组件工具独立保留，不进入公开包。 |
| 合并设备状态与调试页面 | Mac/iPad 状态卡、状态颜色、地址与诊断入口、共享与账户窗口、目录权限、独立维护入口。 |
| 添加运行程序签名状态界面 | 工作管理器的进程、CPU/内存、签名与凭证详情；非法签名和未签名有不同提示。 |

上述界面和任务管理器已在当前源码中，未退回旧版。USB 装置显示设备描述符版本、Windows 提供的端口能力与协商速率；无法从缓存得出的接口 3.1/3.2 版本或通道数仍明确标为未提供，不由速率猜测。

主要源码位置：`desktop/Views`、`desktop/Services/ProcessMonitor.cs`、`internal/app/ipadncm`、`internal/dependencies`、`internal/app/connectioninstall`、`internal/app/macconnection`。

## 找到并修复的问题

1. **目录更名没有贯穿启动校验。** 0.9.3 将桥接程序目录改为可读版本号，但三个启动/恢复检查仍只接受旧哈希目录。0.9.4 已统一接受规范版本号；原有进程、服务、文件、设备和恢复日志核验保留。新目录名字本身不能证明所有权。
2. **组件锁覆盖整个安装过程。** .NET 下载或 Apple 安装可能阻塞已可用的 Wintun，以及取消等待和组件刷新。0.9.5 按组件分别串行，同组件仍防止重复安装，等待可取消，刷新保留进行中的进度。共享目录初次创建单独短暂锁定，避免两个进程同时读取尚未完成的目录标记。
3. **Windows 组件锁缺少系统线程约束。** 原实现未固定等待/释放线程，且没有正确接受已经存在的同名锁。0.9.5 固定系统线程，读取并核验已有锁的管理员权限，使用独立组件锁；不能通过修改未知锁的权限继续安装。
4. **进度窗口共用可变回调。** 同时准备多个组件时关闭一个窗口可能覆盖另一个窗口的更新。0.9.5 改为各窗口独立订阅，关闭后只撤销自己的订阅。
5. **自用离线工具仍按旧源码构建。** 已重新构建工具，使其使用当前受保护的 ProgramData 组件目录，并同步工具校验值、构建记录和整包校验清单。官方组件仍逐个核验原始哈希和所需签名。
6. **删除文件夹被当作普通重装处理。** 手动删除不等于注销服务或安装登记。0.9.5 在下载组件、复制新程序前检查现有安装身份；缺失原始凭据时说明残留原因并停止，不覆盖登记或接管未知服务。有效的中断事务仍交给已有受保护的恢复流程。
7. **构建目录积累旧安装器。** 完整新包审查通过后才清理旧生成的 EXE 和二进制 ZIP；保留当前版本及明确选择的回退版本，保留源码、证据、工具和未知文件。构建通过本身不会把失败候选认定为已验收回退版本。

## 当前目录规则

0.10.0 使用固定 `Program Files/USB Link/App/`，界面位于其 `Desktop/`。配置与账户记录迁到 ProgramData，候选与前一程序仅在更新事务内保留；详见[安装规范](INSTALLATION-LIFECYCLE.zh-CN.md)。0.9.5 私有修复入口保持暂停，0.10.0 尚未在 Windows 上安装或验收。

## 安装与实机证据

- 0.8.139 曾在实际 Windows 上运行，USB 与已有 SMB 共享可用。
- 0.9.2 启动健康检查超时，回退到 0.8.139；没有收到能精确定位缺失组件的候选失败凭据。不能据此断言组件拆分是唯一原因。
- 0.9.3 尝试期间 USB 未恢复；随后用户手动删除整个 Windows 安装目录。未读到完整候选日志，也没有确认回退完成。
- 0.9.4 未安装。0.9.5 暂未安装。
- 通过 U 盘返回的 Windows 本地只读报告已确认：程序目录不存在，安装登记仍是 **0.8.139**，停止的 `USBLinkCore` 指向已删除的 **0.9.3**，核心绑定记录不存在；ProgramData 组件目录及 Windows Temp 恢复目录仍在，没有检测到运行中的 USB Link 程序。
- USB 网络维护通道未恢复；这份报告证明安装残留状态，不能证明 0.9.3 原始启动失败原因或当前驱动、SMB 权限状态。

删除目录后，Windows 本地的服务、SMB 账户、共享和驱动可能仍存在，而原目录中的密码凭据、共享登记和权限恢复记录可能已丢失。不能按名称猜测归属或自动重置这些对象。自用离线目录的只读 `inspect-install.bat` 保存不含密码的安装状态报告。

针对这次报告单独准备了管理员本地修复工具，见 [修复工具说明](../scripts/windows-deleted-install-repair/README.md)。它只接受已删除目录、0.8.139 的完整产品安装登记、已停止且 PID 为零的 0.9.3 服务，复用生产代码的本地安全、服务配置及锁检查。它先检查状态，再复用或离线准备组件；删除残留前把配置与安全描述保存并核验到受保护的 `ProgramData/USB Link/DeletedInstallRecovery/`，再次核验目标后才移除对应残留。程序仍在运行或目标变化就停止。

修复工具固定核验 0.9.5 安装器摘要，启动后等待新版本安装登记、核心绑定、程序文件和运行中服务的连续核验。没有把打开安装器或服务处于运行中等同于 USB/SMB 已恢复；只提取本次启动诊断中的阶段和错误。现有恢复记录、账户、共享、驱动、网络和防火墙设置不由修复工具修改。工具只进入本机自用修复包，普通公开安装器没有缺失绑定后的服务接管入口。

## 检查边界

0.9.5 的完整 Go 竞争检查、原生静态检查、Windows x64 静态检查、架构和源码/历史发布检查通过。新增回归涵盖独立组件准备、同组件重复安装、等待取消、刷新不覆盖活动进度以及并发进度窗口订阅。

Windows 原生锁用例已经交叉检查，但尚未在 Windows 执行。本地残留修复工具通过 Windows x64 编译和静态检查，尚未在目标 Windows 执行。既有 Windows 托管测试失败项仍见 [验证记录](VALIDATION.md)。这些失败与本次硬件启动、USB/SMB 验收均不能由 macOS 检查代替。
