The original failure was not a reason to remove the durable record: failed `declined`/`failed`/`cancelled` writes and lease expiry were clearing the reachable API slot or releasing admission first. The candidate retains both until the same live, positively unlaunched owner persists a terminal transition. Signed bytes and all device recovery receipts remain. Repeating cancellation uses the exact opaque job ID; newer uploads stay blocked until that transition succeeds.

Only a live manager's in-memory reservation can restore a listener slot. A listener cannot borrow another process's durable ownership. The retry compares complete immutable job content, original PID/creation/executable and ID; phase/detail/timestamp may differ because a write result was ambiguous. Every successful replay still invokes the production kernel mutex, actual writer validation and durable CAS. Missing/unreadable/foreign identity fails closed. The initial write's unknown result retains its own ID and bytes; if later reading proves a different durable owner, automatic cancellation remains refused rather than overwriting it.

A positive pre-creation barrier is essential. `committed`/`launchAttempted` are set before native Start. An error returned from Start or a missing worker receipt does not downgrade that barrier. Exact existing worker liveness/recovery checks remain; an unconfirmed launch without an exact handle/PID requires process restart/manual recovery rather than cancellation/new stage. The new status reports `manual_recovery_required` and `worker_creation_unconfirmed`, with USB health independently verified. The timer reacquires the manager mutex before exposing idle retry, so a concurrent launch winner cannot be cancelled.

Fixed recovery controls reuse the existing authenticated `/v1/performance` transport: only `UPGRADEGUARDON` with 900 seconds, `UPGRADEGUARDOFF` or `UPGRADEGUARDSTATE` with 0 seconds, a 32-character lowercase hexadecimal nonce, no extra JSON/query. A retained idle job permits ON renewal and STATE; OFF refuses to discard owned work. Ordinary performance commands, including the iPad live-readback profile, stay blocked. Exact-ID `/v1/cancel` remains available for a previously guarded retained idle job after lease expiry; ack is `persistence_recovered`. A client accepts that only for its exact ID and explicit retry marker. Applying a persistence-retry job is refused; recovery does not launch a worker.

Default OFF boundary: new retention/reservation/state behavior requires a guarded job; legacy failed uploads are unchanged. Protection for an already guarded retained job remains after OFF/expiry, as necessary compatibility safety. The existing always-on native mutex protection prevents legacy writers from replacing a guarded receipt; it is not weakened. No global security policy, Apple pairing, arbitrary path/command API, or system state reset is introduced.
