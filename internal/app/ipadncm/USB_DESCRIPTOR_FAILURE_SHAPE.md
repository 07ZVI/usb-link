# USB descriptor rejection shape (offline, 2026-10-08)

Baseline: `a72067be052823254c32f1abcf52c529fce85439`. This patch diagnoses the existing `USB_STRING_VALUE_INVALID` failure without accepting, trimming, normalizing or repairing any string. The original portable parser, descriptor grant, root binding and live-readback implementation are unchanged.

`Device.usb_serial_failure_shape` is optional. The existing authenticated `IPADNETWORKONLYSTATE` response already contains this Device in `current_usb_descriptor`, so no new route, hardware poll or permission is added. The shape comes from the same completed Hub string-descriptor request that failed the original parser. Read failures with no returned bytes and successfully parsed strings do not attach a shape.

The shape contains only integer counts and booleans: received length capped at 255 bytes; bLength; header/type/length validity; payload UTF-16 unit and odd-byte counts; decoded UTF-8 length; terminal and other NUL counts; Unicode control and whitespace counts grouped into leading/embedded/trailing categories; allowed ASCII serial-character, other ASCII and non-ASCII unit counts; surrogate-pair, unpaired-surrogate and literal replacement counts; and zero/nonzero byte counts outside bLength. Control and whitespace categories may overlap. Within each category, the three position groups partition its total; an all-category payload belongs to leading only. A malformed header never causes inspection outside the capped returned buffer.

Privacy boundary: no raw bytes, serial string, character or code-point sequence, exact position array, failed-value digest, substring, encoding, root-instance suffix or new persistent identity is exported. Multiple different values have exactly the same shape; no reversible serial encoding is provided. The shape intentionally reveals lengths and coarse character categories, including the requested NUL-termination count. This is a bounded diagnostic disclosure, not a cryptographic anonymity guarantee; category counts can still identify constrained cases such as an all-NUL payload. Existing successfully verified identity diagnostics still use their prior accepted-serial SHA256 field; this patch adds no hash of rejected bytes. The exported shape type is regression-checked to contain only int/bool fields, and the Device serial-field whitelist admits this precise shape field alone.

Validation: two-package fresh race run passes (ipadncm 5.615s, ipadsession 2.184s); Windows amd64 vet for ipadncm and the main application passes; Windows ipadncm test executable compiles, but is not executed. The wrapper is compared with the unchanged original parser on 2,172 fixed valid/malformed/random inputs, including truncated/odd/type/UTF-16/padding/value failures; values, statuses and input bytes remain identical. Negative tests distinguish NUL within bLength from zero padding outside it, grouped whitespace from ordinary serial characters, surrogate decoding from literal U+FFFD, and failed UTF-8-length limits. Privacy tests require different same-shape values to serialize identically and reject string/array/reversible diagnostic fields.

The first sandboxed full race attempt could not bind existing localhost mock servers. Re-running with localhost-listening permission passes; no USB device operation is performed by these tests. Native descriptor decoding and the actual failure shape are still pending master-controlled deployment/readback. No assumption is made that the hardware failure is caused by terminal NUL, spaces, length or another class; the parser remains fail closed until live aggregates establish which branch failed.
