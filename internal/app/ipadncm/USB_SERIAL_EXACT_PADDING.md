# Exact observed iSerialNumber padding (2026-10-08, offline candidate)

Baseline: `591c7bef722d175cd101a1b660acc1623123429e`. Sanitized live evidence: project `evidence/0869-hardware/0878-actual-serial-failure-shape.json`. The returned string descriptor had exactly 82 bytes, bLength 82, type 3, 40 UTF-16 units: 24 allowed ASCII serial characters followed by 16 NUL units. There was no embedded NUL, space, non-ASCII, surrogate, replacement character or outside-bLength padding. This evidence supports one precise compatibility rule, not arbitrary NUL trimming or a general USB string policy change.

Only `parseUSBSerialDescriptor` for PID `12AB` can accept that exact shape. The first 24 UTF-16 units must each be ASCII `[A-Za-z0-9._-]` with a zero high byte; all remaining 16 units must be zero; returned length, bLength and type must match exactly. The extracted 24 characters retain their original case and punctuation and must pass the existing stable-serial policy. Any deviation returns the original generic parser's value, status and failure shape unchanged. Unpadded strings also retain their prior generic result and subsequent identity policy.

The Windows reader uses this rule only for device-descriptor `iSerialNumber` (dd16). Product `iProduct` (dd15), language parsing and the generic string parser remain unchanged. There are no extra USB reads. The accepted serial status is the fixed `USB_SERIAL_VERIFIED_EXACT_ASCII24_NUL16_82B`, and `usb_serial_exact_padding_nul_units_consumed` reports 16. A successful parse removes the *failure* shape, but does not remove any native binding or consent requirement. Other serial statuses and shape fields retain their original semantics.

The repository has no authorization predicate comparing `USBSerialReadStatus` to `USB_STRING_VERIFIED`. Actual eligibility still requires the original product/serial identity policy, fresh stable hub/port readback, unique PRESENT root, exact CM root and hub-parent binding, and current owner authorization. The native root's final component must directly match the parsed serial by case folding; no hyphen deletion, location alias or alternate root is introduced. The grant domain and old-consent migration are unchanged: a legacy Windows-instance grant never becomes a descriptor grant automatically, and first explicit confirmation remains required. Descriptor equality in the event watcher and software-restoration scope logic is unchanged.

Diagnostics expose only the fixed format status, consumed count and the existing accepted-serial digest; no original serial, bytes, substring or root suffix is added. The aggregate failure-shape privacy boundary remains as previously documented. Do not infer full device identity or successful native binding merely from the new parsed status.

Offline validation: fresh race for ipadncm, ipadsession and connectioninstall passes; Windows amd64 vet for ipadncm and the main application passes; Windows ipadncm tests compile but are not executed. Pure fixtures test the exact format with unchanged ASCII characters, reject mutations at every prefix and suffix position, enforce prefix 23/25 and suffix 15/17 rejection, and reject wrong PID/header/length/type or any additional returned bytes. The original generic parser and shape wrapper are byte-identical to baseline; unpadded valid strings and 2,168 deterministic random malformed inputs retain baseline values/statuses/shapes. Grant migration, missing-binding refusal and the original descriptor/root/owner tests also pass. A format-specific grant regression confirms that parsing does not promote legacy consent.

Native USB descriptor decoding and the complete root/hub/port binding have **not** been exercised by this candidate's offline checks. Master-controlled signed deployment and authenticated readback are still required. No hardware command, version/resource update, signing or packaging is performed by this branch. Temporary test executables and master-provided immutable hardlink copies are removed after validation; shared source/resource content remains unchanged.
